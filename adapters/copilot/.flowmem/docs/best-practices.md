# 最佳实践指南

本文档汇集了使用 FlowMem 系统的经验总结和高级技巧。

## 核心原则

### 1. 索引优先 (Index-First Strategy)
永远不要试图把整个项目装进脑子里（或上下文里）。
- **project.md** 是地图，不是地形图。它应该通过链接指向 `docs/`。
- 看到 `docs/payment.md` 比看到 500 行支付逻辑说明更有效。

### 2. 拥抱"不知" (Embrace Ignorance)
刚开始任务时，承认自己不知道细节是正常的。
- 不要一开始就 `read_file` 几十个文件。
- 先看地图 (`project.md`)，再看路标 (`docs/`)，最后才看具体的代码。

---

## 🚀 冷启动：如何接手无文档项目？

当你面对一个全新的、没有 `project.md` 的遗留项目时，**绝对不要**把所有代码读一遍。

### ❌ 错误做法
- `read_file src/main.ts`
- `read_file src/utils.ts`
- ... (读取了 50 个文件)
- **结果**：上下文爆炸，成本飙升，遗忘目标。

### ✅ 正确做法 (自举流程)

#### Step 1: 建立骨架
1. **创建基础 `project.md`**：填入空模板。
2. **读取元数据**：`package.json` / `go.mod` / `pom.xml` → 了解技术栈。
3. **读取目录树**：`ls -R` 或 `tree` → 了解模块划分。
4. **填充 project.md**：记录技术栈和大概的模块结构。

#### Step 2: 按需探索 (On-Demand Exploration)
假设任务是"重构 Auth 模块"：
1. **搜索入口**：`grep -r "Auth" .` 或 `grep -r "login" .`
2. **读取核心文件**：只读取搜索到的关键文件。
3. **补充文档**：将理解到的 Auth 逻辑写入 `docs/modules/auth.md`，并在 `project.md` 中添加链接。
4. **开始任务**：此时你只懂 Auth，不懂其他的，**但这足够了**。

## 常见的"坑" (Anti-Patterns)

### 1. 伪更新
- **现象**：`todolist.md` 里全是 `[x]`，但代码一行没改。
- **对策**：Todo 必须对应具体的产出（代码提交或文档变更）。

### 2. 上下文随地大小便
- **现象**：在对话中贴大段 Log 或代码。
- **对策**：存入 `.agentmem/tmp_log.txt`，对话里只发文件名。

### 3. 复读机
- **现象**：反复读取同一个文件，不仅没改动，还把上下文挤占了。
- **对策**：相信自己的记忆（其实是相信 `project.md` 和 `todo` 的记录）。

---

## 错误恢复模式 (Error Recovery)

当工具调用失败时，展示你的 Agentic 能力：

1. **记录错误**：在 `todolist.md` 的 "遇到的问题" 章节记录。
2. **更新假设**：在 "关键问题"章节更新你的假设。
3. **尝试替代方案**：不要死磕同一个路径。

> "错误不是失败，是系统边界的探索。"
