# FlowMem Workflow 优化方案 v2.8 - 概览与问题

## 1. 目标与范围

**目标**:
- 解决 AI 偷懒、遗漏约束、缺乏审核的核心问题。
- 保留四阶段工作流主线，保证产出可追踪。
- Claude Code 全量接入，其他 IDE 用 v1 最简流程。
- 支持 Subagent 上下文隔离与 per-agent 模型/Key 路由。

**范围**:
- 需求澄清、详细规划、执行与审核、交付的流程优化。
- 多 Agent 架构与上下文隔离策略。
- 规则与适配器的接入策略。

## 2. 当前痛点

| 问题 | 表现 | 根本原因 |
|------|------|----------|
| **AI 遗漏约束** | 忽略 common-rules.md、不用 CLI 直接 Edit | 规则过长、无强制机制 |
| **缺乏审核** | 事后检查、AI 自我审核不可靠 | 工作流无内置审核节点 |
| **AI 偷懒** | `console.log('TODO')` 就标完成 | 无质量关卡、无交叉验证 |
| **需求澄清不足** | request.md 过于简单、缺少方案对比 | 流程设计不完善 |
| **透明度不足** | 不知道 AI 在哪个阶段、进度不直观 | 无状态反馈机制 |
| **上下文隔离缺失** | 多角色共用同一上下文，审核失效 | 缺少隔离执行机制 |
| **Token 预算不足** | 大仓库/跨模块任务上下文超载 | 无统一的上下文打包策略 |
| **多工具接入难** | Claude Code/Trae/Copilot 能力不一致 | 缺少分层接入方案 |
| **Key 冗余** | 同一用户需重复配置多 Key | 缺少 per-agent 路由与默认回退 |

## 3. 关键结论摘要

- 四阶段工作流主线保持不变：需求澄清 → 详细规划 → 执行与审核 → 交付。
- Claude Code 走 Subagent 路径实现上下文隔离；主会话 Orchestrator 负责推进与校验。
- ccq-engine 作为可选检索增强层，默认优先使用工具内置检索。
- 支持 per-agent 模型/Key，无 key 时回退默认模型，不阻塞流程。
- 其他 IDE 采用 v1 最简流程（单会话 + 固定产出文件）。
- 复杂任务可增加 `.agentmem/implementation/` 细化层，提供结构/伪代码/接口说明用于确认。
- 引入 Claude Code hooks 作为 AI 行为门禁（写入拦截/质量门禁/留痕）。
- 借鉴 OMC 的 skills 分层、模板继承、升级信号、notepad 机制，但保持独立实现。

## 4. 术语表

> 本文档统一使用英文术语，避免中英混用导致的歧义。

| 术语 | 定义 | 备注 |
|------|------|------|
| **Agent** | 具有明确职责的 AI 角色，负责特定任务 | 如 Analyst、Solver、Coder 等 |
| **Subagent** | Claude Code 子代理，拥有独立上下文窗口和执行循环 | 与主会话隔离，通过文件交接 |
| **Orchestrator** | 主会话协调者，负责阶段推进和产出校验 | 不作为独立 Subagent 存在 |
| **Phase** | 工作流阶段 | Phase 1-4 对应需求澄清到交付 |
| **Todo** | 单个可执行任务项 | 存储在 todolist.md 中 |
| **Acceptance** | 验收条件 | 每个 Todo 的完成标准 |
| **Context Curator** | 上下文打包 Agent | 负责压缩和整理检索结果 |
| **Reviewer** | 代码审核 Agent | 检查代码质量和偷懒行为 |
| **Critic** | 方案审核 Agent | 检查技术方案的可行性 |
| **Hook** | Claude Code 钩子 | 在特定事件触发时执行的脚本 |
| **ccq-engine** | 可选的检索增强引擎 | 用于大仓库或跨会话场景 |

### 术语使用规范

1. **Agent 相关**
   - 使用 "Agent" 而非 "角色" 或 "代理"
   - 使用 "Subagent" 而非 "子代理" 或 "子 Agent"
   - Agent 名称首字母大写：Analyst, Solver, Critic, Planner, Coder, Reviewer

2. **流程相关**
   - 使用 "Phase" 而非 "阶段"（在正式描述中）
   - 使用 "Todo" 而非 "任务项" 或 "待办"
   - 使用 "Acceptance" 而非 "验收条件"（在代码/配置中）

3. **文件相关**
   - 使用 `.agentmem/` 而非 "记忆目录"
   - 使用 `request.md` 而非 "需求文档"
   - 使用 `todolist.md` 而非 "任务清单"
