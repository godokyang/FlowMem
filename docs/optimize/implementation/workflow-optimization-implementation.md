# FlowMem Workflow 优化方案 v2.7 - 实施方案

**对应设计文档**: `../design/workflow-optimization-proposal.md`

---

## 1. 实施范围与目标

**范围（In Scope）**:
- Orchestrator 状态机与 Agent 调用链路
- 需求评分与追问（Analyst）
- 方案迭代与审核（Solver + Critic）
- 任务拆解与执行（Planner/Coder）
- 代码审核与质量门槛（Reviewer）
- 高风险变更升级门槛与测试兜底策略
- 写入拦截器与审计留痕
- 适配器规则同步（build-adapters）

**范围外（Out of Scope）**:
- 引入新的外部模型提供商
- UI/前端可视化看板
- 与第三方 CI/CD 平台的深度集成

**目标**:
- 降低规则违规率与“偷懒输出”
- 增加可追溯性与可审计性
- 明确 Agent 职责边界，减少误解与流程跳步

---

## 2. 里程碑与 MVP

| 里程碑 | 目标 | 交付内容 | 通过标准 |
|---|---|---|---|
| MVP 1 | 先解决偷懒与绕过 | Reviewer 审核、写入拦截器、需求评分追问 | 关键路径可阻断违规；能稳定生成 request.md |
| MVP 2 | 打通完整流程 | Solver+Critic 迭代、WBS 规划、执行循环 | 端到端流程可跑通；高风险可升级 |
| GA | 稳定发布 | 配置化策略、审计留痕、适配器同步 | 回归测试通过；文档与示例完备 |

## 3. 任务拆解与验收

### 3.1 Orchestrator 与 Agent 链路
- **任务**: Orchestrator 状态机流程落地，串联 Analyst/Solver/Critic/Planner/Coder/Reviewer
- **验收**:
  - 必经节点不可跳过（Analyst/Critic/Reviewer）
  - 阶段输出与 `.agentmem` 文件一致

### 3.2 需求评分与追问
- **任务**: 完整性评分、追问生成、阈值自适应
- **验收**:
  - 低于阈值必追问
  - 评分与阈值逻辑可配置

### 3.3 方案迭代与审核
- **任务**: Solver + Critic 迭代两轮上限
- **验收**:
  - Critic 反馈可回注 Solver
  - 超过两轮触发用户介入

### 3.4 执行与审核
- **任务**: Coder 执行 + Reviewer 审核 + 重试机制
- **验收**:
  - Reviewer 可拦截低质量实现
  - 高风险变更需要用户确认

### 3.5 写入拦截器与审计留痕
- **任务**: 受保护文件写入拦截 + trace 日志
- **验收**:
  - 直接写入 `.agentmem` 关键文件会被拒绝
  - 关键决策有可回放日志

### 3.6 适配器同步
- **任务**: common-rules 更新后生成适配器
- **验收**:
  - build-adapters 输出与规则一致

## 4. 风险与回滚

**主要风险**:
- 风险分级误判导致频繁打断或漏拦截
- 测试不可跑导致流程卡死
- Agent 命名与职责不一致导致链路断裂
- 审计日志过大导致上下文膨胀

**回滚策略**:
- 配置开关降级到旧流程（只保留核心拦截）
- 禁用高风险升级，回退为 Reviewer 单审
- 暂停自动重试，改为人工介入
- 保留现有 `.agentmem` 文件结构，不做破坏性改动

---

## 5. 测试与发布计划

**测试计划**:
- 单元测试: CLI 命令、解析器、拦截器逻辑
- 集成测试: 端到端流程（request.md → todolist.md → 执行 → 交付）
- 风险测试: 高风险变更必须触发确认
- 文档校验: 规则与示例一致

**发布计划**:
1. 内部验证（Alpha）: 选取 2-3 个真实任务验证流程
2. 小范围试用（Beta）: 开放给有限用户，观察拦截与审核反馈
3. 正式发布（GA）:
   - 更新 npm 包与 changelog
   - 运行 `build-adapters` 同步适配器
   - 发布实施与使用说明

**发布准入**:
- 关键路径测试通过
- 规则文档与示例一致
- 回滚策略与配置开关可用
