## MVP 0：验证核心假设（2 任务点）

> 目标：验证 Reviewer 能否有效检测"偷懒代码"

- [ ] **0.1.1** 实现偷懒检测规则
  - 检测 `console.log('TODO')` 模式
  - 检测 `// TODO: implement` 注释
  - 检测空函数体 ``
  - 检测 `throw new Error('Not implemented')`
  - 检测硬编码测试数据

- [ ] **0.1.2** 实现 acceptance 条件校验
  - 解析 todo 的 acceptance 字段
  - 逐条验证是否满足
  - 输出校验结果

- [ ] **0.1.3** 输出结构化审核报告
  - 定义报告 YAML frontmatter 格式
  - 实现报告生成逻辑
  - 输出到 `.agentmem/logs/review-{todo_id}.md`

### 0.2 MVP 0 验证

- [ ] **0.2.1** 准备 10 个标准测试用例
  - 3 个正常实现（应通过）
  - 3 个偷懒实现（console.log/TODO/空函数）
  - 2 个部分实现（缺少错误处理）
  - 2 个边界情况（命名不规范/缺少注释）

- [ ] **0.2.2** 执行验证测试
  - 手动触发 Reviewer 审核
  - 记录检出率
  - 目标：偷懒代码检出率 ≥90%

## MVP 1：解决偷懒问题（8 任务点）

> 目标：建立基础的质量门禁机制

### 1.1 Subagent 权限配置（2 任务点）

- [ ] **1.1.1** 定义 Subagent 权限模型
  - Analyst: 只读
  - Solver: 只读
  - Critic: 只读
  - Planner: 只读 + 写 todolist.md
  - Coder: 读写代码文件
  - Reviewer: 只读 + 写审核日志

- [ ] **1.1.2** 实现权限控制机制
  - 基于 Claude Code Subagent 配置
  - 测试权限隔离效果

### 1.2 需求评分 + 追问机制（3 任务点）

- [ ] **1.2.1** 实现 Analyst Agent
  - 定义评分维度（目标明确性/预期结果/边界范围/约束条件）
  - 实现 4-D 分析流程（DECONSTRUCT/DIAGNOSE/DEVELOP/DELIVER）
  - 输出到 `.agentmem/analysis.md`

- [ ] **1.2.2** 实现追问逻辑
  - 评分 < 7 时触发追问
  - 生成 2-3 个具体问题
  - 整合用户回答后重新评分

- [ ] **1.2.3** 实现评分阈值控制
  - 可配置阈值（默认 7）
  - 支持用户跳过追问

### 1.3 flowmem guard CLI 基础实现（1 任务点）

- [ ] **1.3.1** 实现 check-protected 命令
  - 检查保护文件列表
  - 返回拦截/允许状态

- [ ] **1.3.2** 实现 check-risk 命令
  - 读取高风险路径配置
  - 检查 Reviewer 通过标记

- [ ] **1.3.3** 实现 log-change 命令
  - 记录变更到 trace.jsonl
  - 包含时间戳、工具、路径

- [ ] **1.3.4** 配置 Claude Code hooks
  - PreToolUse: Edit/Write 拦截
  - PostToolUse: 变更记录

## MVP 2：完整核心流程（16 任务点）

> 目标：实现四阶段工作流完整闭环

### 2.1 Solver + Critic 方案迭代（3 任务点）

- [ ] **2.1.1** 实现 Solver Agent
  - 接收需求 + 上下文
  - 输出技术方案到 `.agentmem/plan.md`
  - 支持根据 Critic 反馈修改

- [ ] **2.1.2** 实现 Critic Agent
  - 审核清单（方向/可行性/完整性/风险/一致性）
  - 输出审核结果到 `.agentmem/review.md`
  - 区分 Critical/Major/Minor 问题

- [ ] **2.1.3** 实现迭代控制
  - 最多 2 轮迭代
  - Critic 通过后进入下一阶段
  - 2 轮仍不通过则升级用户

### 2.2 WBS 分解（2 任务点）

- [ ] **2.2.1** 实现 Planner Agent
  - 接收 request.md
  - 按 WBS 方法分解任务
  - 输出到 `.agentmem/todolist.md`

- [ ] **2.2.2** 定义 todolist.md 格式
  - YAML frontmatter（元信息）
  - 任务列表（id/content/acceptance/status/risk）
  - 依赖关系

### 2.3 执行循环（3 任务点）

- [ ] **2.3.1** 实现 Coder Agent
  - 接收单个 todo + 上下文
  - 执行代码修改
  - 遵循项目规范

- [ ] **2.3.2** 实现执行循环控制
  - 遍历 todolist
  - 调用 Coder → Reviewer
  - 更新 todo 状态

- [ ] **2.3.3** 实现重试策略
  - 第 1 次：根据反馈修改
  - 第 2 次：重新检索上下文
  - 仍失败：升级用户

### 2.4 Context Curator（3 任务点）

- [ ] **2.4.1** 实现触发条件检测
  - token 使用率 > 60%
  - 检索结果 > 15 文件
  - 跨目录 ≥ 3
  - 单文件 > 500 行

- [ ] **2.4.2** 实现上下文打包逻辑
  - 筛选关键文件
  - 提取关键代码片段
  - 生成依赖关系图

- [ ] **2.4.3** 输出 context.md
  - 定义输出格式
  - 记录 token 节省量

## 实施顺序建议

```
MVP 0 (2点) → MVP 1 (8点) → MVP 2 (16点) → 完整流程 (13点)
     ↓              ↓              ↓              ↓
  验证假设      质量门禁      核心闭环      生产就绪
```

**关键里程碑**：

| 里程碑 | 完成标准 | 任务点 |
|--------|----------|--------|
| M0 | Reviewer 偷懒检出率 ≥90% | 2 |
| M1 | 基础质量门禁可用 | 8 |
| M2 | 四阶段流程完整闭环 | 16 |
| M3 | 生产环境可用 | 39 |
